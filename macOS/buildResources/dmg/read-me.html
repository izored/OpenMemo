openMemo
Read me first. Installing is one drag, and the first launch is four clicks.

Install

Drag openMemo onto the Applications folder in this window. That is the whole install.

Then macOS blocks it once, and that is expected

openMemo is not notarised by Apple. Notarising needs a paid Apple developer account, which this project does not have. macOS treats every app it cannot check the same way: it refuses the first launch and makes you allow it by hand. Nothing is wrong with the download.

  1. Open openMemo from Applications

    macOS refuses, and this dialog offers no way through. Click Done. Do not click Move to Bin.

    “OpenMemo” Not Opened
    Apple could not verify “OpenMemo” is free of malware that may harm your Mac or compromise your privacy.
    DoneMove to Bin

  2. Open System Settings, then Privacy & Security

    Apple menu, System Settings, Privacy & Security in the sidebar. Scroll down to Security. openMemo is named there, with a button beside it. Click Open Anyway.

    “OpenMemo” was blocked to protect your Mac.
    Open Anyway
    That line only appears after step 1, and it fades after a while. If it is not there, try opening the app again.

  3. Confirm with Touch ID or your password

    macOS checks that you own the Mac. Use Touch ID, or click Use Password and type your account password.

  4. Say yes one last time

    A final dialog appears, this one with a way through. Click Open Anyway. openMemo starts, and it starts normally from now on.

    Open “OpenMemo”?
    Apple is not able to verify that it is free from malware that could harm your Mac or compromise your privacy.

If you set a PIN lock

The lock keeps its PIN in your macOS login keychain, and the keychain recognises apps by their signature. openMemo signs itself rather than paying Apple to, so every build looks like a new app to the keychain. The first launch after an install or an update asks for your login password. Type it and choose Always Allow, and the PIN keeps working.

If you click Deny, the lock screen rejects the correct PIN, because openMemo can no longer read what it stored. Quit openMemo, delete the lockEnabled and lockBlob lines from ~/Library/Application Support/OpenMemo/openmemo-desktop.json, then set a new PIN in Settings.

Updating later

openMemo checks GitHub for new versions and offers to download the new .dmg for you. When one arrives:

  1. Quit openMemo first

    Command-Q, not just closing the window. The backend holds the database open.

  2. Drag the new openMemo onto Applications and replace

    Finder asks whether to replace. Say yes.

  3. Allow it again

    A fresh download carries a fresh block, so page one applies to every update, not only the first install.

Your library is not inside the app

Everything you keep lives in ~/Library/Application Support/OpenMemo/. Replacing the app replaces the program and nothing else. Memos, media, settings and your PIN stay where they are, and openMemo copies the library into its backups folder before the first launch of a new version.

Never delete that folder to reinstall cleanly. That folder is your library. Throwing away the app is harmless. Throwing away that folder is not.

Faster way, if you use Terminal

Files a browser downloads carry a hidden quarantine tag, and that tag is what triggers the blocking. Removing it skips all four steps:

xattr -dr com.apple.quarantine /Applications/OpenMemo.app

Same result as clicking through, one line. Run it after each update.
