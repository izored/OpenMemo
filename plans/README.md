## Findings considered and rejected (do not re-audit)

These were raised by the audit subagents and rejected during vetting — recorded so
they don't resurface:

- **"Chat DB session leaks on client disconnect"** — false. The save session opens
  only *after* the token loop ends (`chat.py`); cancellation skips it entirely. The
  real issue (lost reply) is `plans/008`. There is no session leak.
- **"CI never runs vitest / frontend tests"** — false. `.github/workflows/ci.yml`
  has an explicit `npm run test` step.
- **"`is_processed=True` set even when Chroma upsert fails"** — false. The failure
  path leaves `is_processed` False; the real defect is *silence*, fixed by `plans/007`.
- **"Chat sessions not persisted / no multi-turn context"** — false. `ChatSession`
  + `Message` tables persist, history is loaded server-side in `chat.py`, and the
  frontend tracks `session_id` and renders a history list (`AskMemoPage.tsx:317`).
- **"AudioContext created every render in VoiceRecorder"** — false. It's held in a
  ref (`VoiceRecorder.tsx:65`).
- **Chrome extension `<all_urls>` host permissions** — by design; saving an
  arbitrary page is the extension's purpose. Revisit only if it's published to the
  Chrome Web Store.
- **Delete check-then-act race (commit before Chroma purge)** — the window is
  milliseconds and search already filters `is_deleted`; the durable problem is the
  silent-purge-failure read path, folded into `plans/009`. Not worth a separate
  concurrency fix for a single-user local app.
